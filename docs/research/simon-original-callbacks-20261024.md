# Simon original graph: implementation evidence

This checkpoint adds `simon_source.observe_graph` / `validate_graph`, a bounded
preflight ingredient for the original executor. It does not dispatch the graph or
claim live cinematic acceptance. It checks the full ten-element authored wrapper
array, exact root/action/class paths, exact Reference/Inline selection, complete
typed observations, and changed identities. The five presentation stages remain
intro, exact battle `_C_1`, exact phase transition, exact battle `_C_0`, outro.
The persistent-flag, inventory and sound tail is deliberately included and
disclosed; a partial prefix cannot masquerade as the unchanged original graph.

Eight focused tests exercise real Catalog/StoredArray/StoredStruct values,
selection/order/truncation/identity/class-package rejection and projected reads.

## Experimental original executor adapter

`simon_original.prepare(scope, disposable_test=True)` prepares an experimental
original Simon graph. The flag declares that the caller has independently
verified disposable save/config isolation; the adapter neither creates that
isolation nor performs travel. It retains the exact graph and all three exact
original sequence assets, validates source parameters and the original current-
world outro exit, and requires readable current history and idle
original services. Source observations do not replace native call validation.

`PreparedSimon.start()` rechecks current world/controller, selected slot, history
and idle services immediately before one-shot dispatch through the existing
explicit typed `prepare_blueprint` API. It does not widen the older narrow
cinematic allowlist or use its source-byte repeat override. The game original
Sequential instance owns every child and callback. `poll()` is observation only;
even idle after activity proves neither victory nor cinematic visibility.
Unknown dispatch acknowledgement is quarantined and never retried. `close()`
releases only SDK planning/asset leases and leaves game-owned actors/actions alone.

Thirty-three new adapter/source/arena/final-readiness tests pass, including a real InvocationPlanner and
Blueprint v8 wire encoding for the executor's object parameter (8-byte parameters,
16-byte allocation). With existing original-game-action and Blueprint regression
tests and the paired adapter regressions, 77 pass. No live dispatch acceptance
is established by these tests.

The native copied-soft-path codec is consumed through `StoredSoftObjectPath`,
never by guessing a source reference from successful asset loading. Exact source
extraction additionally resolved the nested transition field: it is a
`ByteProperty` backed by `S_GameFlowTransitionType`, not `EnumProperty`. The
adapter requires that exact transition struct, observed value 2, selected live
descriptor enum identity and current non-sentinel enum membership. This reuses
the existing codecs without an invented enum layout. Unsupported field reads
still block preparation with the exact field name before dispatch.

Both exact TriggerBattle sources are also checked against the SHA-pinned
`_original_trigger_recipes.json` recipes and existing `_verify_source` roster
reader. Their soft references must identify the original Simon arena; any hard
reference must reciprocate that same observed actor. The actor must already be
loaded in the exact current world, have the exact authored class/root component,
and retain its authored root frame. No arena loading, construction, movement or
fallback is performed. The current controller's battle manager must be idle with
complete empty player/enemy arrays and no arena. Source graph and dependencies
are re-read immediately before dispatch, so an arena disappearing after initial
preparation blocks without setting the dispatch-attempt flag.

Both original adapters now re-read history/selected slot and observe idle
executor/cinematic services **after** their full dependency recheck, immediately
before recording the dispatch attempt. Cross-adapter tests simulate another
action beginning, unreadable history, and the selected slot changing during those
dependency reads; each blocks without invoking the original graph. A played-ID
change alone remains subject to the original game policy and does not block. This remains
a Python preflight, not an atomic replacement for native identity checks.

## Original continuation authority

Three exact demonstrated packages were extracted into the ignored isolated build
directory using the existing package index and read-only retoc procedure. No game
mutation or registry scan was needed. Cooked function parsers checked complete
serialized/virtual function extents; copied source assets are not part of Git.

| Original package basename | Cooked SHA256 |
|---|---|
| BP_GameActionInstance_Sequential | `fb9ce45b9e2bfdaba36f3f1b1bc41de6176c0e0013b318eb8fb73731fbf6dcb2` |
| BP_GameActionInstance_ChildExecutor | `2a8b3376c964b4154967f93ac9185ec6eece9c7cb52a786b0a6f8f60cc3205bd` |
| BP_GameActionInstance_TriggerBattle | `1e7451ff8cfe3cf3f54abaae0fcc2b949a641345ba554e25f97ae925f6652b89` |

All belong to `/Game/Gameplay/GameActionsSystem/`, respectively beneath
`SequentialGameAction`, `Utils` and `TriggerBattle`.

- Sequential `TryExecuteNextGameAction` tests `NextIndex < array length`, obtains
  the next wrapper while incrementing NextIndex, then invokes
  `TryExecuteChildGameAction`. Exhaustion broadcasts the original
  `OnGameActionExecutionFinishedDelegate(self)` at virtual offset 89.
- ChildExecutor creates each original child instance with itself as Outer,
  assigns `GameAction`, stores `ChildGameActionInstance`, binds the child's
  finished delegate to `OnChildGameActionFinished`, and executes it with the
  original current player controller. Its completion handler removes that
  binding and clears its own child reference.
- Sequential's override aggregates `ShouldTriggerAutoSaveAfterExecution`, calls
  the superclass completion handler, then advances through the original helper.
  It blocks autosaves during execution and exposes its aggregated requested
  autosave flag after execution.
- TriggerBattle binds its exact `OnBattleFinished` callback before calling
  `StartBattleNEW` with the source action's Battle Start Params. Completion
  unbinds that callback and broadcasts the original game-action finished delegate.
  `Victory` is stored by the event but is **not branched on** in this function.
  A reload may retire the whole world/executor; Python must not infer victory
  from idle or re-create continuation in a replacement world.

These facts support executing the original Sequential machinery rather than
constructing a Python stage timer. They do not authorize any arbitrary Blueprint
call or alteration of the source array.

## Original repeat policy and unverified repeatability

The exact cached `BP_GameAction_CinematicWithLightingScenario` CDO and the three
Simon action payloads supply `AllowRepeat=false`. That value does **not** prove
that played cinematics are skipped. In the decoded original
`ValidateCinematicParameters`, offset 5 initializes `local_IsValid=true`.
Offsets 836–1065 evaluate `ID != None && HasPlayedCinematic(ID) && !AllowRepeat`;
the matching branch formats a warning, calls `PrintStringInLog` at offset 1784,
and pops flow at 1804. No branch assigns `local_IsValid=false`. Offset 2247 copies
that still-true value to the output and 2266 returns. The caller's validation
branch at 3088 therefore continues normal preparation for played IDs.

Both original adapters preserve this warning-only policy. They still require
readable current-world history and a stable selected slot, but do not clear
history, force `AllowRepeat`, or reject a played ID. Their status reports
`repeat_policy="original"` and `repeat_verified=false`; this source correction
does not establish successful visible repeated runs. Each prepared dispatch
remains one-shot and an unknown acknowledgement remains quarantined.

The decoded source is the exact local
`duelliste-cinematic-lifecycle-v192/decoded-functions.txt` capture. The older
native direct-cinematic source-byte override is not used by these adapters and
was not changed as part of this correction.

## Portable full-encounter source requirements

The overworld phase experiment qualifies the core phase sequence's translated
spawned presentation, not all three cinematics or the original outer graph in a
new world. The existing original-world adapter remains unchanged.

The exact leaf introduction `CS_SimonIntro` contains 48 spawnables and 62
possessables. Its eleven root possessables include the placed Cine Simon, three
swords, a rock, UltraVolumetrics, SkyLight, SpotLight, DirectionalLight,
LightingScenario and ReadingCube. The exact leaf outro `CS_SimonOutro` contains
31 spawnables and 54 possessables. Its twelve roots include Cine Simon,
SimonPlaceHolder, EclipsePhase2, two UltraVolumetrics actors, two battle
spotlights, SkyLight, SpotLight, DirectionalLight, LightingScenario and
ReadingCube. The master assets reference these leaf scenes. The ignored source
inventories preserve their exact binding GUIDs, parents and tracks; friendly
binding labels alone are not actor identity or duplication authority.

The decoded original CinematicSystem receives `CinematicParameters`, creates its
own player and actor, then handles the `SpawnableActors` tag map through
`AddBindingByTag`. The inspected authored parameter structs expose no transform
origin or arbitrary GUID-binding context. Pre-cinematic camera blending and
post-cinematic game-flow transition fields are not relocation transforms.
Consequently, copying only a cinematic action and changing its sequence path
cannot supply the already-qualified SDK-owned origin mechanism. That mechanism
currently applies only to actors created under its native SDK factory owner.

A callback-preserving portable implementation needs a scoped owned runtime graph:

- Retain and validate the complete original ten-action source graph, each exact
  class, original battle source/roster and all presentation dependencies.
- Create owned runtime Sequential/action objects whose wrapper array follows the
  original order. Keep original Sequential/ChildExecutor/TriggerBattle callback
  logic; do not infer victory from an idle battle manager or use a stage timer.
- Substitute battle arena references and isolated battle policy only in owned
  parameter copies, using the existing owned-arena/source provenance checks.
- For each cinematic, establish an owned player/context bridge before original
  playback, apply the destination-minus-authored-origin translation to private
  instance data, and bind any required placed actors to explicitly owned copies.
  Never write shared source assets or mutate an unrelated game-created player.
- Replace the original-world outro exit soft reference with an owned return
  context for the initiating current-world exploration pawn. The original exit
  invokes `TeleportCharacter`; leaving it unchanged can relocate the pawn into
  the natural encounter range. Do not globally suppress that natural trigger.
- Decide campaign-tail policy explicitly in the runtime specification. Omitting
  reward/progression actions is a replay variant and must not be described as an
  unchanged ten-action campaign graph.

No existing API supplies this complete runtime graph/sequence bridge. Existing
`OriginalTriggerFight.poll()` deliberately reports `idle_retained`, not a victory
or an original child-finished callback; chaining its two direct fights in Python
would discard the original callback authority. Source manifests and bounded
validation can be prepared independently, but do not establish portable playback
or native clone authority. No portable dispatch or new capability is added here.

## Portable preparation follow-up

`PortableSimon.preload()` now provides an explicit owning-thread warm-up before
`start()`. It retains the exact three original presentation assets, the shared
Simon action source and the original arena/trigger classes in a dedicated child
scope. It creates no arena, trigger or battle. A frontend may call this while
preparing its encounter UI. `start()` also performs it when no earlier warm-up
was requested; that fallback moves preparation before the introduction and does
not promise that first-use loading disappears.

The return pawn and position are captured freshly at `start()`, allowing ordinary
movement after warm-up within the same world/controller. A replaced preload
context rejects entry. Future native asset/source/geometry/dispatch checks are
retained. Unknown asset acknowledgements preserve the owner and cannot be
replayed; deferred/unknown lease releases do not become successful cleanup.

Construction metadata reuse is bounded to at most 64 positively stabilized
function/CDO identities, scoped to the same transport and world/controller.
Each reuse performs fresh selected-identity reads; no pawn/arena pose, source
values, grounding result or dispatch permission is cached. Zero serials are
never treated as wildcards. World/transport changes trigger fresh discovery.

The direct-fight preparation now measures asset retention, idle checks,
construction inputs, arena-frame validation, native arena construction,
grounding/clearance, camera focus, trigger construction, arena binding, entry
validation and dispatch. Portable status retains both battle timing summaries,
plus current battle timings. These are diagnostic measurements, not a speed
claim; the updated preloader/cache still needs live timing comparison.

Camera-path occlusion remains unqualified. The existing arena ground profile
checks actual spawn anchors and the observed exploration capsule, plus its
bounded approach route when requested. It does not trace the original cinematic
camera paths or animation envelope. Camera-focus refresh also does not prove
that branches or foliage cannot obscure the camera. Portable status explicitly
reports `camera_path_clearance_qualified=false`. A future exact-sequence camera
profile must prove its translated authored camera samples and use a bounded
native scene-volume/line query before claiming clearance; an open-looking party
space is not substituted for that evidence.
